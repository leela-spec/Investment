# Tool Landscape

**Evidence date:** 2026-08-23. “Current” refers to official documentation/repository state observed on that date. Product feature claims below are facts from the linked primary sources; fit/status is an R3 judgment.

## Decision summary

| Component | Strong function | Important limit | R3 status |
|---|---|---|---|
| Karakeep | Human web/PDF capture, snapshots, notes, tags, highlights, API | Application state/backup is not the neutral canonical manifest; capture quality varies by site | **ADOPT NOW** as capture/review interface, not evidence truth |
| Zotero | Scholarly metadata, translators, citations, PDF annotation | Narrower content indexing; export is explicitly not backup | **TEST FURTHER** as optional academic workspace |
| Paperless-ngx | Document inbox, OCR, correspondents/tags, API | Oriented to document management, not web-version/citation provenance | **DEFER** unless scanned administrative docs become a core corpus |
| Filesystem + SQLite FTS5 | Immutable originals, portable manifests, BM25/metadata retrieval | Needs small ingestion/search glue and no polished capture UI | **ADOPT NOW** as canonical evidence substrate |
| DuckDB FTS | Convenient analysis alongside existing IPOS DuckDB | FTS index does not update automatically | **DEFER** as read-only analytics, not primary search |
| Tantivy | Mature embedded Rust search engine | New language/runtime and custom schema glue | **DEFER** until SQLite benchmark fails |
| Meilisearch | Rich search service/API | Always-on service; current license is mixed MIT/BUSL | **REJECT** for baseline personal KB |
| Typesense | Search server/API | Extra service/operations and server license constraints | **REJECT** for baseline personal KB |
| Docling | Broad structured local conversion, tables/layout, JSON/Markdown | Heavy dependency/model footprint; parser output still requires validation | **ADOPT NOW** as default parser after isolated compatibility test |
| GROBID | Scholarly header/reference/citation extraction into TEI | JVM/service footprint; specialization, not general parser | **TEST FURTHER** for academic PDFs only |
| Apache Tika | Very broad MIME detection, text/metadata extraction | Lower semantic structure for complex financial tables/layout | **ADOPT LATER** as format fallback if Docling coverage fails |
| OCRmyPDF + Tesseract | Adds text layer to scanned PDFs with deterministic command record | OCR can introduce errors and requires language packs | **TEST FURTHER** only for image-only PDFs |
| ArchiveBox | Multi-format web preservation including WARC/SingleFile | Additional always-on archive stack overlaps Karakeep | **DEFER**; revisit for regulated/WARC-grade capture |
| Obsidian/local Markdown | Excellent portable human notes over files | Proprietary app; not capture, preservation or authoritative indexing | **OPTIONAL VIEW**, never canonical dependency |

## Capture and library systems

### Karakeep

Karakeep v0.33.0 represents everything as a bookmark. Official docs say link captures can include metadata, previews, screenshots and archives; PDFs/media are content-extracted and searchable; notes, highlights and attachments remain searchable. Its API exposes bookmarks, lists, tags, highlights, assets and backups, and its search endpoint searches title/content/description/notes. The official SingleFile integration can upload client-side page captures and can append a new asset rather than overwrite it. These are strong inbox and review capabilities.

Sources: [bookmarking](https://docs.karakeep.app/using-karakeep/bookmarking/), [API](https://docs.karakeep.app/api/karakeep-api/), [search](https://docs.karakeep.app/api/search-bookmarks/), [SingleFile integration](https://docs.karakeep.app/integrations/singlefile/), [backup API](https://docs.karakeep.app/api/list-backups/), [AGPL-3.0 license](https://github.com/karakeep-app/karakeep/blob/main/LICENSE).

**Judgment:** use it to capture, triage and annotate. Export each accepted artifact plus metadata into the neutral evidence contract. Do not make bookmark IDs, tags generated by AI, or the application database the only provenance. Capture both the remote original and a rendered snapshot where useful; these are different artifacts.

### Zotero

Zotero has mature JavaScript web/import/export/search translators with test cases and an automated testing process. It provides high-quality bibliographic metadata, DOI-oriented workflows, duplicate management and citation formatting. Its local full-text index covers PDF, EPUB, HTML and plain text; official docs explicitly exclude DOCX/ODT and default to 500,000 characters per file. Zotero documents that RDF exports can include files/notes but also warns that export is **not a backup** and item data may change on round-trip.

Sources: [translator development and tests](https://www.zotero.org/support/dev/translators), [full-text limits](https://www.zotero.org/support/preferences/search), [export warning](https://www.zotero.org/support/kb/exporting), [data-directory backup](https://www.zotero.org/support/zotero_data), [AGPL-3.0 code](https://github.com/zotero/zotero/blob/main/COPYING), [translator source](https://github.com/zotero/translators).

**Judgment:** excellent optional workspace for papers and citations, but not the one general evidence store. If adopted, store the neutral `evidence_id` in an Extra/custom field and keep exported attachment hashes; Zotero must not become a second canonical object store.

### Paperless-ngx

Paperless-ngx consumes documents, performs OCR when configured, applies document types/correspondents/tags, offers full-text search and exposes a REST API. Its administration documentation covers backup/export and its source is GPL-3.0. This is mature document-management software.

Sources: [API](https://docs.paperless-ngx.com/api/), [administration/export](https://docs.paperless-ngx.com/administration/), [advanced usage](https://docs.paperless-ngx.com/advanced_usage/), [GPL-3.0 license](https://github.com/paperless-ngx/paperless-ngx/blob/dev/LICENSE).

**Judgment:** strong for invoices and scanner workflows, but it overlaps the recommended parser/index and does not solve web capture versions, financial identifiers or scholarly citations. Adding it now creates a third stateful library.

### ArchiveBox and SingleFile

ArchiveBox preserves URLs into multiple formats using established external tools and exposes APIs. SingleFile creates a portable HTML capture in the browser; Karakeep officially integrates it and supports retaining multiple uploaded versions. ArchiveBox is MIT-licensed.

Sources: [ArchiveBox docs](https://docs.archivebox.io/latest/), [ArchiveBox API](https://docs.archivebox.io/dev/apidocs/), [MIT license](https://github.com/ArchiveBox/ArchiveBox/blob/dev/LICENSE), [Karakeep SingleFile integration](https://docs.karakeep.app/integrations/singlefile/).

**Judgment:** SingleFile through Karakeep is enough for the initial human workflow. Test ArchiveBox only if WARC capture, replay fidelity, link extraction or scheduled crawl breadth becomes a measured requirement.

## Canonical store and search

### Filesystem objects + manifests

The most durable free substrate is content-addressed files plus sidecar records:

```text
evidence/
  objects/sha256/ab/<full-sha256>
  records/<evidence-id>.json
  derived/<evidence-id>/<parser-and-version>/document.json
  derived/<evidence-id>/<parser-and-version>/document.md
  index/evidence.sqlite
  exports/
```

The file hash is physical identity; a record ID represents the acquisition/version event. JSON records are the recovery/export contract. SQLite is a rebuildable index, not the only metadata copy.

### SQLite FTS5

FTS5 is built into SQLite distributions, operates in-process and provides BM25 ranking, phrase/prefix/NEAR/Boolean/column queries, highlighting and snippets. Ordinary relational tables supply exact metadata/entity filters and foreign keys. SQLite is public domain.

Sources: [FTS5](https://www.sqlite.org/fts5.html), [copyright/public-domain statement](https://sqlite.org/copyright.html).

**Judgment:** this is sufficient for a personal evidence corpus and aligns with IPOS's local, deterministic, minimal-service design. Store parser text and titles in FTS; keep identifiers/tags/entity aliases in normalized relational tables. Measure corpus/query latency before adding another engine.

### DuckDB FTS

DuckDB offers a full-text-search extension with stemming and BM25, but its documentation warns that an index does not update automatically when the source table changes and must be recreated. IPOS already uses DuckDB for operational facts.

Source: [DuckDB FTS extension](https://duckdb.org/docs/stable/core_extensions/full_text_search).

**Judgment:** do not mix evidence blobs/search lifecycle into the operational warehouse. DuckDB may query exported evidence manifests/Parquet for batch analytics, while SQLite handles incremental search.

### Tantivy, Meilisearch and Typesense

Tantivy is an MIT-licensed embedded Rust full-text library; it offers a credible scale-up route without a separate server but requires custom binding/schema work. Meilisearch and Typesense provide capable network search services and richer typo/facet behavior but add service operations, synchronization, backups and license review. Meilisearch's repository license is currently `MIT AND BUSL-1.1`, not unqualified MIT.

Sources: [Tantivy repository/license](https://github.com/quickwit-oss/tantivy), [Meilisearch license](https://github.com/meilisearch/meilisearch/blob/main/LICENSE), [Typesense repository](https://github.com/typesense/typesense).

**Judgment:** none is justified before SQLite FTS5 has a measured failure (for example, index size/query latency or multilingual tokenization that cannot be solved locally). “Better search” is not evidence of need.

### Obsidian/local Markdown

Markdown is a good derivative and annotation/export format. Obsidian reads local files and is free for personal use, but the desktop application is proprietary and its vault model does not itself provide acquisition receipts, immutable originals, parser lineage or structured financial identifiers.

Sources: [Obsidian local-file help](https://help.obsidian.md/Files+and+folders/How+Obsidian+stores+data), [license](https://obsidian.md/license).

**Judgment:** allow Obsidian or any editor to view annotations/derived Markdown. Do not rely on plugins for canonical ingestion or metadata integrity.

## Parsing, OCR and citation extraction

### Docling

Docling converts PDF, office, HTML, CSV, images, email and XBRL XML into a unified document representation and exports lossless JSON plus Markdown/text. Its official examples separate deterministic standard conversion from optional VLM/ASR/enrichment paths. The code and packaged agent skill are MIT-licensed.

Sources: [supported formats/outputs](https://docling-project.github.io/docling/usage/supported_formats/), [agent skill](https://docling-project.github.io/docling/usage/agent_skills/), [source/license](https://github.com/docling-project/docling/blob/main/LICENSE).

**Judgment:** default parser for bounded accepted documents. Pin the version/model assets; record configuration; disable remote/VLM enrichments in baseline; retain confidence and validate financial tables against originals.

### GROBID

GROBID is a specialized machine-learning pipeline and REST service for turning scholarly PDFs into structured TEI, including bibliographic references and citation contexts. It publishes evaluation information and is Apache-2.0 licensed.

Sources: [official documentation](https://grobid.readthedocs.io/en/latest/), [Apache-2.0 license](https://github.com/grobidOrg/grobid/blob/master/LICENSE).

**Judgment:** use only when Docling/Zotero metadata is insufficient for academic citation graphs. It is not the general parser.

### Apache Tika

Apache Tika detects/extracts text and metadata from a very broad set of formats using mature parsers, including PDFBox and optional Tesseract OCR, and supports archive formats such as WARC/WACZ. It is Apache-2.0 licensed.

Sources: [supported formats](https://tika.apache.org/3.3.0/formats.html), [license](https://github.com/apache/tika/blob/main/LICENSE.txt).

**Judgment:** reliable fallback for MIME/text/metadata, not the preferred financial layout/table parser.

### OCRmyPDF/Tesseract

OCRmyPDF adds a searchable text layer to scanned PDFs while retaining an auditable command/output artifact and uses Tesseract OCR. OCR is probabilistic and can change recognition with versions/language packs; it must never replace the original scan.

Sources: [OCRmyPDF documentation](https://ocrmypdf.readthedocs.io/en/latest/), [OCRmyPDF MPL-2.0 license](https://github.com/ocrmypdf/OCRmyPDF/blob/main/LICENSE), [Tesseract repository/license](https://github.com/tesseract-ocr/tesseract).

**Judgment:** route only image-only or low-text PDFs to OCR. Record OCR version/languages and retain page-level confidence where available.

## Deterministic processing map

| Need | Reuse | Deterministic baseline | AI role |
|---|---|---|---|
| Web capture | Karakeep + SingleFile; optional ArchiveBox | URL normalization, HTTP receipt, byte hash, capture version | None required |
| Document parsing | Docling; Tika fallback | Pinned parser/config, lossless JSON/Markdown hash | VLM disabled by default |
| Scanned PDF | OCRmyPDF/Tesseract | Image-only detector, pinned languages/options | None required |
| Scholarly citations | Zotero translators; GROBID when needed; Crossref/DataCite metadata | DOI normalization, bibliography fields and exact source link | May suggest missing matches, never overwrite |
| Entity/ticker extraction | SEC identifiers, GLEIF LEIs, versioned alias tables, exact-pattern rules | Authoritative identifier joins and reviewed alias updates | NER suggestions in review queue only |
| Deduplication | Hash/URL/DOI/accession/LEI keys; optional SimHash candidate generation | Exact hash and identifier constraints | No silent semantic merges |
| Source classification | Allowlisted domains, connector/source rules, MIME/document-type rules | Versioned rules with test fixtures | Suggest unknown class only |
| Retrieval | SQLite relational filters + FTS5/BM25 | Offline exact/tag/entity/text queries | Optional reranking/embeddings |
| Summary/claims | No battle-tested deterministic truth extractor exists | Source anchors and structured review status | Clearly derived, model/versioned, human-reviewed |
| Contradictions | Existing IPOS contradiction rules for operational facts; evidence candidate comparison separately | Compare normalized typed claims only after reviewed extraction | Candidate generation/explanation only |

## Rejected assumptions

- An “AI” label is not a feature unless the deterministic inputs, outputs, model dependency and failure mode are inspectable.
- A bookmark application's full-text index is not source provenance.
- A citation manager export is not a backup merely because it contains attachments.
- A vector database does not solve preservation, licensing, identity, versioning or citation anchors.
- Existing IPOS DuckDB reuse does not justify coupling two different lifecycles into one database.
